# The scheduled task prompt

Two scheduled tasks run this fleet — one in the morning, one in the evening, Israel time.
Each starts a **fresh session with no memory of any previous run**, which is why the
prompt below is fully self-contained and why all state lives in git.

This file is the canonical copy of that prompt. If you change how a cycle runs,
change it here and update the scheduled tasks to match.

---

## Morning prompt

```
Run the morning upgrade cycle for the Porto/Douro/Gerês trip planner.

1. Clone the private repo:
     gh repo clone <OWNER>/porto-douro-trip /tmp/trip
     cd /tmp/trip
   (If gh is not installed: install it, then authenticate with the token in the
   repo secret / your stored credentials.)

2. Read CLAUDE.md, then run one full cycle:
     bin/run-cycle.sh morning

   If `claude -p` is unavailable in this environment, run the same cycle yourself
   using the Task tool: spawn one subagent per spec file in .claude/agents/
   (scout-douro, scout-nature, scout-porto, scout-coast, and stays in parallel;
   then logistics; then planner; then critic), passing each agent its spec file
   to follow. Then run `python3 bin/convergence.py score` and commit.

   `festival-scout` and `scout-food` are Codex-only roles today, so they are not
   part of the Claude fallback unless matching `.claude/agents/` specs are added.

3. Push the result. The commit message is generated by the script; do not
   overwrite it.

4. Report back in Hebrew, briefly:
   - the phase before and after, and the stability score
   - what actually changed in the itinerary this cycle
   - anything new in trip/open-questions.md that needs Ariel to decide

If state/phase already says `converged`, do nothing beyond a one-line report
saying the plan has converged.

Do not ask clarifying questions — nobody is watching. Make reasonable choices,
state your assumptions in the commit, and proceed.
```

## Evening prompt

Identical, except step 2 runs:

```
     bin/run-cycle.sh evening
```

The evening cycle skips fresh scouting. It re-checks feasibility, integrates the day's
research, and scores convergence. Mornings widen the plan; evenings tighten it.

## Optional visual digest task

Use this as a separate scheduled task when you want a human-friendly gallery email with
images, Google Maps links, and review links for places the itinerary is already converging on.

```
Run the visual digest task for the Porto/Douro/Gerês trip planner.

1. Clone the private repo:
     gh repo clone <OWNER>/porto-douro-trip /tmp/trip
     cd /tmp/trip

2. Read AGENTS.md, then run:
     python3 bin/validate-agent-fleet.py
     python3 bin/build-visual-report.py

   If the Codex CLI is available and configured, you may instead run:
     bin/run-agent-codex.sh visual-reporter

3. If the generated HTML changed, commit and push it.

4. Report back briefly in Hebrew:
   - whether `state/visual-report.html` changed
   - which places were highlighted
   - whether the environment had an authenticated mail capability; if not, say the HTML is ready but mail was not sent

Do not ask clarifying questions. Do not invent photos or review links.
```

## Why it converges instead of churning forever

Each cycle the planner is constrained by `state/phase`, and `bin/convergence.py`
only promotes the phase when the itinerary genuinely holds still across cycles.
The planner's spec says explicitly that a no-change cycle in `refine` or `lock`
is a success — without that, an agent asked to "improve the plan" will always find
something to reword, and the score never settles.

Once the phase reaches `converged`, `bin/run-cycle.sh` exits immediately. The
scheduled tasks keep firing but cost nothing, so if you later add a fact that
shakes the plan loose, the loop picks it back up on its own.
